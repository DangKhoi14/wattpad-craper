# Wattpad Chapter Scraper

A toolkit to extract chapter lists, download chapter content, and combine multi-part chapters from Wattpad stories into local `.txt` files.

---

## Project Structure

```
.
├── get_code_list.py      # Step 1: Extract chapter codes from a story's table of contents
├── wattpad_scraper.py    # Step 2: Download chapter content using extracted codes
├── combining.py          # Step 3: Merge multi-part chapters into single files
├── normalize_dots.py     # Utility: Normalize dot sequences in existing .txt files
├── chapters.txt          # Generated by get_code_list.py — input for wattpad_scraper.py
├── wattpad_chapters/     # Output of wattpad_scraper.py — one .txt file per chapter part
└── wattpad_combined/     # Output of combining.py — one .txt file per combined chapter
```

---

## Workflow

### Step 1 — Extract Chapter Codes

Edit the `url` variable in `get_code_list.py` to point to your target story's table of contents page:

```python
url = "https://www.wattpad.com/<story-id>-<story-slug>"
```

Then run:

```bash
python get_code_list.py
```

This will:
- Open Chrome and load the story's table of contents
- Extract numeric chapter codes from each entry
- Write all codes to `chapters.txt`, one per line

Example `chapters.txt` output:
```
1444698477
1444698936
1444699010
```

---

### Step 2 — Download Chapter Content

```bash
python wattpad_scraper.py
```

This will:
- Read chapter codes from `chapters.txt`
- For each code, fetch `https://www.wattpad.com/<code>`
- Handle internal pagination (`page/2`, `page/3`, ...) automatically
- Extract only story paragraphs via `<p data-p-id="...">` (skips ads, comments, UI noise)
- Normalize dot sequences: runs of 6+ dots are reduced to exactly 5 (`"....."`)
- Extract chapter title from the page `<header>` and use it as the filename
- Save content to `wattpad_chapters/<title>.txt`
- Stop automatically if a file already exists (avoids re-downloading)

---

### Step 3 — Combine Multi-Part Chapters (Optional)

Wattpad splits long chapters into parts (e.g. `Chapter 1191 (1)`, `Chapter 1192 (2)`...). `combining.py` merges them:

```bash
python combining.py
```

Or with explicit paths:

```bash
python combining.py wattpad_chapters wattpad_combined
```

**Grouping logic:**
- A file ending in `(1)` starts a new combined chapter
- Consecutive files with incrementing part numbers are merged into one
- A file with no part number is treated as standalone
- Parts are separated by 3 blank lines in the output

**Output filename format:** `Chapter n - m. Title.txt` (or `Chapter n. Title.txt` if single-part)

Example:
```
wattpad_combined/
├── Chapter 1191 - 1195. Sao mọi chuyện lại thành ra như vậy chứ.txt
├── Chapter 1196 - 1200. Rốt cuộc làm thế nào mà ngài chịu đựng được.txt
└── ...
```

## Anti-Bot Behavior

`wattpad_scraper.py` uses several strategies to avoid detection:

- **Selenium with Chrome** — renders JavaScript like a real browser
- **Webdriver property spoofing** — hides automation fingerprint via `navigator.webdriver = undefined`
- **Random delays** — waits 1.5–3s between sub-pages, 4–8s between chapters
- **Chrome flags** — disables `AutomationControlled` and `useAutomationExtension`
- **Vietnamese locale** — sets `--lang=vi-VN` to match expected regional behavior

---

## Output

Each downloaded chapter is saved as a `.txt` file:

```
wattpad_chapters/
├── Chapter 1191. Sao mọi chuyện lại thành ra như vậy chứ (1).txt
├── Chapter 1192. Sao mọi chuyện lại thành ra như vậy chứ (2).txt
└── ...
```

- Filename sanitized: forbidden characters removed, max 100 characters
- Fallback: if header title not found, first line of content is used as filename
- Encoding: UTF-8
- Dot normalization applied before saving (6+ dots → `"....."`)

---

## Known Limitations

- Wattpad may throttle or block if requests are too frequent — increase sleep delays if needed
- Content extraction relies on `<p data-p-id="...">` tags; Wattpad HTML structure changes may break parsing
- Next-chapter navigation relies on `#story-part-navigation` or anchor text `"continue to next part"`
- `get_code_list.py` does not implement retry logic — re-run manually if the page fails to load
